## What this package is

Lucide icons for Flutter, drawn with `CustomPainter` from generated Dart data.
Split out of `elk_icon_picker` (sibling repo `../elk_icon_picker`, which depends on
and re-exports this package) on 2026-09-29. Published on pub.dev — publish this
before any picker release that needs a new version of it.

## Rules

- No external dependencies — ever. Ask before adding anything.
- Public API is the barrel file lib/elk_lucide_icons.dart — any new
  public class or function must be exported there.
- No picker/UI concerns here (e.g. `CategoryStyle` lives in the picker).

## Architecture

See FILES.md for the full file index. Quick summary:
- `lib/elk_lucide_icons.dart` — public barrel file (only export point)
- `lib/src/gen/lucide_icons.g.dart` — **GENERATED, do not edit by hand**
- `lib/src/widgets/lucide_icon.dart` — `LucideIcon` CustomPainter widget
- `lib/src/services/icon_search_service.dart` — search + rename-safe `findByName`

## Gotchas

- `lucide_icons.g.dart` is generated by `tool/generate_lucide_icons.dart` from Lucide's published
  source (github.com/lucide-icons/lucide, ISC licensed). Zero external dependencies (`dart:io` /
  `dart:convert` only) — downloads each icon's SVG + JSON metadata directly from GitHub.
  Run `dart run tool/generate_lucide_icons.dart` (~40s for all icons) or add `--limit=N` for a
  quick smoke test against `--out=<scratch path>`. `--source=<dir>` reads a local clone of the
  Lucide repo instead of the network (pins output to that clone's commit; also works where
  api.github.com is blocked). Always `dart format` the output and run
  `flutter analyze` after regenerating — ask the user before swapping in new data, since upstream
  Lucide renames/removes icons occasionally.
- The generator emits relative imports (`../models/...`), so `lib/src/gen/` and `lib/src/models/`
  must stay siblings.
- Renamed icons: the generator reads each icon's upstream `aliases` and emits a `@Deprecated`
  `LucideIcons.<oldName>` constant plus a `kLucideIconAliases` map (old name → current name).
  Host apps store icons by name string, so they must look up with
  `IconSearchService.findByName()` (resolves aliases, returns null) rather than
  `kLucideIcons.firstWhere` (throws on a renamed name).
- `.github/workflows/check-lucide-updates.yml` regenerates weekly and opens an issue on drift; it
  formats with the language version from `pubspec.yaml`'s SDK constraint.
